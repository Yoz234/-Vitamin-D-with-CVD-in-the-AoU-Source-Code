# Execution guide

Notebook numbers identify the original workflow layers. Several are conditional audits or recovery alternatives; they are not one unconditional sequence. Python/R companions preserve cell order, including original default execution switches. Read the notebook first and use the intended kernel.

## Q1 and Q2

1. Prepare the authorized Q1/Q2 runtime and existing data directory. The maintained `01_q1_q2_workflow.ipynb` accepts `q1_followup_person_level_v2.csv` and `q1_covariate_table_v3_bmi.csv` (or the v2 covariate table). An existing `analysis_base_clean.csv` is the fallback when those inputs are unavailable. These files are deliberately absent here. Optional supporting modules have their own input requirements; for example BMI recovery consumes the earlier covariate table. They are not a replacement for the missing original full raw-CDR cohort builder.
2. Open `Q1_Q2/01_q1_q2_workflow.ipynb`. Set `CAPSTONE_DATA_DIR`, `CAPSTONE_OUTPUT_DIR`, and the authorized `WORKSPACE_CDR` before setup. Run common preparation and the required analysis blocks. The preserved source leaves `run_q1_workflow(base)` commented and calls `run_q2_workflow(base)` by default. Uncomment Q1 when required. `run_full_workflow()` is also defined; avoid executing both routes unintentionally.
3. Q2 rebuilds CRP using the maintained concept/unit mapping, fits correlation and log-log/extended models, and constructs/audits candidate covariates. Its original main CRP selection is nearest same-day/pre-index CRP without a universal 30-day restriction. Do not silently equate it with the later Q3 CRP30 analysis. The manuscript table workflow contains Q2 30-/90-day sensitivity checks.
4. `Q1_Q2/02_q1_final_manuscript_revisions.ipynb` contains four independent final revision blocks: Table 1; the subgroup forest plot; the primary Cox table; the OMOP concept table. These require pre-existing inputs and results. The forest plot reads `q1_subgroups_all.csv`, `q1_interaction_tests.csv`, and `q1_overall_hr.csv`; the main Cox block reads `analysis_base_clean.csv`. Table 1 additionally requires `vitd_baseline_versions.csv` and the baseline/follow-up files. Where these blocks use `/home/jupyter/capstone/data`, replace that example working directory with the actual authorized directory. Run only the relevant blocks.
5. `Q1_Q2/03_q1_q2_manuscript_tables.ipynb` is the separate 2026-08-27 manuscript table and supplemental-audit workflow. Configure `WORKSPACE_NAME`, `MIGRATION_ROOT`, `DATA_DIR`, and `OUT_DIR` in its first code cell for the authorized server folder layout; this retained source does not use `CAPSTONE_DATA_DIR`. It reads existing baseline, Cox, follow-up, vitamin D, concept, CRP, BMI, eGFR, subgroup, and Q2 model inputs; required versus optional reads appear in the source. It includes additional refits/audits. Inspect its source-status reports instead of assuming missing optional results were generated.

The `support/` notebooks are preserved modules, not independent turn-key programs. Some expect variables produced in an earlier interactive session. Their first markdown cells record their source and dependencies. The final revision blocks override corresponding older figure/table presentation blocks; preserve the cohort/model distinctions when comparing tables.

## Q3 existing genetic analysis

- **Clinical rebuild:** if needed, run upstream notebook 06 in the authorized Q3 CDR. Notebook 07 repairs carrier availability after an empty denominator; 08 probes prep sample names/denominators. Use them only for their stated conditions. Notebook 09 builds model-preparation inputs from the successful rebuild directory.
- **Carrier sensitivity:** R notebooks 11 and 12 fit the earlier carrier model and PH sensitivity. They require an R/IRkernel runtime and `survival`. They do not implement additive dosage.
- **Resources/QC:** upstream 13 checks available resources. Genetics 14 Hail extraction performs QC/LD and can export analytic-cohort genotypes. The separate `14_...stage_once_then_export` is a recovery/export alternative for its stated runtime condition. Do not assume both 14 variants need to run. Preserve genotype coding and sample-ID mapping checks.
- **Additive models:** notebook 15 joins analytic inputs and additive ALT dosage and fits models. `15_...r_fallback_fixed` is the corrected recovery route after model datasets 04/05 already exist and the older fallback fails; it does not rebuild Hail inputs. Retained source 15 still includes its original fallback, so use the explicitly corrected notebook when that failure occurs.
- **Validation:** notebook 17 checks harmonization, genetic PCs, relatedness, ancestry-specific HWE feasibility, and LD/haplotype feasibility. It does not establish that each item is available or that adjustment succeeded. Notebook 19 records R availability/environment.

Set the source notebooks' `Q3_VDR_DATA_DIR` and relevant input/output variables explicitly; defaults reflect historical server folder names. Use a separate output directory for a fresh rerun. Q1/Q2 and Q3 were developed in different authorized CDR/runtime contexts; do not force a shared CDR release or shared participant denominator.
